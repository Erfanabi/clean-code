# مستندات رسمی

مستندات رسمی «منبع حقیقت» هستند. وقتی درباره‌ی رفتار دقیق یک ویژگی زبان یا ابزار شک داری، به‌جای وبلاگ‌ها اول سراغ این‌ها برو.

## زبان‌ها

| منبع | کاربرد |
|---|---|
| [TypeScript Handbook](https://www.typescriptlang.org/docs/handbook/intro.html) | راهنمای رسمی TypeScript؛ مرجع اصلی ماژول ۰۶ |
| [TSConfig Reference — strict](https://www.typescriptlang.org/tsconfig#strict) | توضیح تک‌تک گزینه‌های tsconfig، به‌خصوص strict mode |
| [TypeScript Playground](https://www.typescriptlang.org/play) | آزمایش سریع کد TypeScript در مرورگر |
| [MDN — JavaScript](https://developer.mozilla.org/en-US/docs/Web/JavaScript) | مرجع کامل و دقیق JavaScript |

## راهنماهای سبک کدنویسی (Style Guides)

| منبع | کاربرد |
|---|---|
| [Google TypeScript Style Guide](https://google.github.io/styleguide/tsguide.html) | قواعد نام‌گذاری، import، تایپ‌ها و ساختار فایل در گوگل؛ مرجع ماژول ۰۱ و ۰۶ |
| [Google JavaScript Style Guide](https://google.github.io/styleguide/jsguide.html) | معادل JavaScript |

**نکته:** Style Guide قانون جهانی نیست؛ قرارداد یک تیم است. ارزش اصلی آن «ثبات» (Consistency) است. در پروژه‌ی واقعی، Style Guide تیم خودت بر هر منبع دیگری مقدم است.

## ابزارها

| ابزار | مستندات | نقش در بوت‌کمپ |
|---|---|---|
| Vitest | [vitest.dev/guide](https://vitest.dev/guide/) | اجرای تست‌ها (ماژول ۱۲ و همه‌ی مثال‌ها) |
| ESLint | [eslint.org/docs](https://eslint.org/docs/latest/) | تحلیل ایستا و کشف Code Smellهای ساده |
| typescript-eslint | [typescript-eslint.io](https://typescript-eslint.io/) | قوانین ESLint مخصوص TypeScript |
| Prettier | [prettier.io/docs](https://prettier.io/docs/) | فرمت‌دهی خودکار؛ تا بحث‌های سلیقه‌ای از Code Review حذف شوند |
| Node.js | [nodejs.org/docs](https://nodejs.org/docs/latest/api/) | مرجع API های Node.js برای ماژول‌های ۰۹ و ۱۳ |
