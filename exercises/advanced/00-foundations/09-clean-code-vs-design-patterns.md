# تمرین پیشرفته — درس ۹: Clean Code در برابر Design Patterns

> درس مرتبط: [Clean Code در برابر Design Patterns](../../../docs/00-foundations/09-clean-code-vs-design-patterns.md)

## تمرین: تکامل تدریجی یک سیستم تخفیف

این تمرین تجربه‌ی «الگو در زمان درست» را شبیه‌سازی می‌کند. هر مرحله را **کامل** کن (کد + تست سبز) و **بعد** مرحله‌ی بعد را بخوان. اگر از Git استفاده می‌کنی، هر مرحله یک Commit باشد.

**مرحله‌ی ۱:** دو نوع تخفیف: درصدی و مبلغ ثابت. مبلغ نهایی منفی نمی‌شود. (همان نسخه‌ی ساده‌ی درس؛ از صفر خودت بنویس.)

**مرحله‌ی ۲:** نوع سوم: «۲ بخر، ۱ ارزان‌ترین رایگان». حالا تخفیف به **اقلام سبد** نیاز دارد، نه فقط مبلغ کل. امضای تابع چه تغییری می‌کند؟

**مرحله‌ی ۳:** نوع‌های چهارم و پنجم: «تخفیف پلکانی» (۵٪ بالای ۱ میلیون، ۱۰٪ بالای ۳ میلیون) و «تخفیف اولین خرید» (به تاریخچه‌ی مشتری نیاز دارد).

**مرحله‌ی ۴:** تیم مارکتینگ می‌خواهد چند تخفیف **ترکیب** شوند، با قاعده‌ی «حداکثر ۳۰٪ کل».

**خواسته در هر مرحله:**

- کد و تست.
- یک یادداشت کوتاه: «در این مرحله آیا ساختار جدیدی (الگو) معرفی کردم؟ چرا الان و نه زودتر؟»

**خواسته‌ی پایانی:**

1. در کدام مرحله Strategy (جدول توابع) معرفی شد؟ آیا با Rule of Three هماهنگ بود؟
2. در مرحله‌ی ۴ آیا الگوی دیگری (مثلاً Composite یا Decorator) به ذهنت رسید؟ استفاده کردی یا نه؟ چرا؟
3. اگر از روز اول همه‌ی ساختار مرحله‌ی ۴ را می‌ساختی، چه هزینه‌ای در مراحل ۱ تا ۳ پرداخته بودی؟
