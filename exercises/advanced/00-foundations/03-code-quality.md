# تمرین پیشرفته — درس ۳: کیفیت کد

> درس مرتبط: [کیفیت کد](../../../docs/00-foundations/03-code-quality.md)

## تمرین: گزارش کیفیت یک پروژه‌ی واقعی

یکی از پروژه‌های واقعی خودت (ترجیحاً یک پروژه‌ی React یا Next.js که روی آن کار کرده‌ای) را انتخاب کن. اگر کد شرکت است و نمی‌توانی آن را به اشتراک بگذاری، فقط **نتایج و تحلیل** را بفرست، نه کد را.

**خواسته:**

1. **سنجش خودکار:**
   - `tsc --noEmit` را با `"strict": true` اجرا کن (اگر پروژه strict نیست، فقط تعداد خطاها را بشمار؛ لازم نیست اصلاحشان کنی).
   - ESLint را با قانون `complexity: ['warn', 10]` اجرا کن و ۵ تابع با بیشترین پیچیدگی را فهرست کن.
   - تعداد `any`، `@ts-ignore` و `eslint-disable` را بشمار (مثلاً با `grep -r`).
2. **سنجش تغییرات:** با دستور زیر، ۱۰ فایل پرتغییر سه ماه اخیر را پیدا کن:

</div>

```bash
git log --since="3 months ago" --name-only --pretty=format: | sort | uniq -c | sort -rn | head -10
```

<div dir="rtl">

3. **تحلیل Hotspot:** فایل‌هایی که **هم** در فهرست پیچیدگی و **هم** در فهرست پرتغییر هستند، Hotspot تو هستند.
4. **گزارش:** یک گزارش فارسی حداکثر یک صفحه بنویس: سه Hotspot برتر، علت پیشنهادی مشکل هر کدام، و یک اقدام کوچک و مشخص برای هر کدام (در حد یک PR).

**معیار پذیرش:** گزارش بر اساس داده است، نه حدس؛ اقدام‌ها کوچک و قابل اجرا هستند.
