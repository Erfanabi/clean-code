# تمرین پیشرفته — درس ۵: نگهداشت‌پذیری

> درس مرتبط: [نگهداشت‌پذیری](../../../docs/00-foundations/05-maintainability.md)

## تمرین: ماژول درگاه پرداخت قابل گسترش

فروشگاه فعلاً با دو درگاه پرداخت کار می‌کند و تیم کسب‌وکار گفته احتمالاً در شش ماه آینده یک یا دو درگاه دیگر اضافه می‌شود. هر درگاه:

- یک نام نمایشی فارسی دارد.
- حداقل و حداکثر مبلغ قابل پرداخت دارد.
- کارمزد درصدی دارد.
- یک API برای «ساخت لینک پرداخت» و یک API برای «تأیید پرداخت» دارد که امضا و فرمت پاسخ‌شان برای هر درگاه **متفاوت** است.

**خواسته:**

1. طراحی‌ای در TypeScript بساز که در آن **اضافه کردن درگاه سوم** فقط به یک فایل جدید و یک خط در یک ثبت مرکزی نیاز داشته باشد، و فراموش کردن هر بخش، خطای کامپایل بدهد.
2. منطق مشترک (بررسی بازه‌ی مبلغ، محاسبه‌ی کارمزد، انتخاب درگاه‌های مجاز برای یک مبلغ) فقط یک بار نوشته شود.
3. فراخوانی‌های شبکه را با یک Interface انتزاعی کن تا تست‌ها بدون شبکه اجرا شوند.
4. **درگاه سوم را واقعاً اضافه کن** و تعداد فایل‌ها و خطوطی که تغییر کرد را گزارش بده.
5. در یک پاراگراف بنویس: کجای طراحی‌ات ممکن است **Over-engineering** باشد؟ چه چیزی را عمداً **ساده** نگه داشتی؟

**معیار پذیرش:** `npm run check` سبز؛ گام ۴ به حداکثر ۲ فایل دست زده است.
