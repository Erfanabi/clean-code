## تمرین ۱: بازپرداخت یک بدهی با تست

قاعده‌ی «تخفیف دانشجویی ۱۵٪، فقط برای سفارش‌های زیر ۲ میلیون تومان» در سه جا پیاده شده است:

</div>

```typescript
// cart.ts
export const studentPrice = (total: number) => (total < 2_000_000 ? total * 0.85 : total);
// invoice.ts
export const studentDiscount = (total: number) => (total <= 2000000 ? Math.round(total * 0.15) : 0);
// promo-banner.ts
export const studentSavingText = (total: number) =>
  total < 2e6 ? `${Math.floor(total * 0.15)} تومان صرفه‌جویی` : '';
```

<div dir="rtl">

**خواسته:**

1. **قبل از تغییر**، تست‌هایی بنویس که **ناهماهنگی‌ها** را آشکار کنند. (راهنمایی: مبلغ دقیقاً ۲٬۰۰۰٬۰۰۰ و مبلغی که ۱۵٪ آن اعشاری می‌شود.) چند ناهماهنگی پیدا کردی؟
2. برای هر ناهماهنگی، یک سؤال برای تیم کسب‌وکار بنویس.
3. با فرض پاسخ «زیر ۲ میلیون یعنی اکیداً کمتر، و همه جا گرد به نزدیک‌ترین تومان»، یک `student-discount-policy.ts` بساز و سه فایل را از آن استفاده کن.
4. تست‌های نهایی بنویس.

**محل کد:** `playground/00-foundations/06-technical-debt/intermediate-1.ts`

## تمرین ۲: نامه به مدیر

سناریو: ماژول «قیمت‌گذاری» در ۶ ماه گذشته ۲۴ بار تغییر کرده است. هر تغییر به طور میانگین ۱.۵ روز طول کشیده و ۳ باگ مالی در Production ایجاد شده که مجموعاً ۵ روز کار اضطراری گرفته است. تیم تخمین می‌زند با ۶ روز کار (جمع کردن قواعد، تست، جدول قیمت) هر تغییر به نیم روز برسد.

**خواسته:** یک پیام کاری فارسی (حداکثر ۱۵۰ کلمه) به مدیر بنویس که:

- با یک عدد شروع شود، نه با «کد کثیف است».
- نقطه‌ی سربه‌سر (Break-even) را محاسبه کند.
- ریسک انجام **ندادن** را بگوید.
- یک پیشنهاد مشخص و محدود بدهد (نه «همه چیز را بازنویسی کنیم»).
