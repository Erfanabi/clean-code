# تمرین‌های مبتدی — درس ۶: بدهی فنی

> درس مرتبط: [بدهی فنی](../../../docs/00-foundations/06-technical-debt.md)

## تمرین ۱: ربع بدهی

هر سناریو را در یکی از چهار ربع بدهی فنی قرار بده و دلیلت را بنویس:

1. تیم برای نمایش در نمایشگاه پنج‌شنبه، صفحه‌ی دمو را بدون تست ساخت و یک تیکت «پاک‌سازی دمو» با تاریخ مشخص برای هفته‌ی بعد ثبت کرد.
2. یک توسعه‌دهنده‌ی تازه‌کار همه‌ی State اپلیکیشن را در یک Context بزرگ گذاشته چون نمی‌دانست راه دیگری هم هست.
3. تیم بعد از یک سال فهمید «سفارش» و «سبد خرید» دو مفهوم جدا در دامنه‌اند ولی در کد یکی شده‌اند.
4. مدیر گفت «وقت برای تست نداریم» و این جمله در سه Sprint پشت‌سرهم تکرار شد.
5. تیم آگاهانه از یک کتابخانه‌ی قدیمی استفاده کرد چون مهاجرت ۳ هفته طول می‌کشید؛ تصمیم در یک ADR با شرط «مهاجرت قبل از پایان پشتیبانی کتابخانه» ثبت شد.
6. کسی یک `// @ts-ignore` گذاشت چون خطا را نمی‌فهمید.

## تمرین ۲: TODOهای خوب

این TODOها را به TODOهای مفید تبدیل کن (شناسه‌ی تیکت را خودت بساز):

</div>

```typescript
// TODO fix
// TODO: refactor this mess
// FIXME!!!
// TODO: remove later
```

<div dir="rtl">

برای هر کدام یک **زمینه‌ی فرضی** هم بنویس (مثلاً «این تابع تخفیف را دو بار اعمال می‌کند وقتی...»). یک TODO خوب به خواننده می‌گوید: **چه** مشکلی، **چرا** مهم است، **کی** یا تحت چه شرطی باید حل شود، و **کجا** پیگیری می‌شود.
